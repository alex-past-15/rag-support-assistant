# RAG-ассистент для поддержки продавцов

Ассистент отвечает на вопросы о карточках товаров по справке Яндекс Маркета. Например, какие фото можно загрузить, где найти архивные товары или как изменить артикул. Вместе с ответом он показывает ссылки и цитаты, чтобы можно было проверить, откуда взялась информация.

Если ответ не проходит проверку, ассистент сообщает об этом и предлагает передать вопрос оператору. Модель работает локально через Ollama, платный API не нужен.

Это пет-проект на открытой документации. Он не связан с Яндексом и не имеет доступа к кабинету продавца.

## Зачем нужен проект

В поддержке часто повторяются вопросы, ответы на которые уже есть в справке. Но продавцу всё равно приходится искать нужную статью и разбираться в её условиях.

Идея проекта — сделать этот поиск проще. Продавец задаёт вопрос обычным языком и получает ответ со ссылкой на инструкцию. Если разобраться не удалось, оператору можно передать вопрос вместе с найденными материалами.

Для бизнеса это может означать меньше однотипных обращений и меньше времени на поиск инструкций. Пока это предполагаемая польза: проект не использовался в реальной поддержке, поэтому цифр экономии или снижения нагрузки нет.

## Что умеет

- Ищет ответы в 20 статьях о карточках, фото, характеристиках, категориях, артикулах и статусах товаров.
- Показывает ответ, ссылки на статьи и цитаты из них.
- Проверяет, подтверждаются ли утверждения источниками и отвечают ли они на вопрос.
- Отказывается отвечать, если проверка не пройдена.
- Сохраняет обращения в очередь, где их можно посмотреть и закрыть.

Очередь работает в самом проекте. Кнопка «Передать оператору» записывает обращение в SQLite, а не отправляет его в поддержку Яндекса.

## Стек

Python, Streamlit, FAISS, Sentence Transformers, Ollama и SQLite. Для сбора статей используются Beautiful Soup и markdownify.

Модель для ответов — **Qwen3 4B Instruct**, для поиска — **multilingual-e5-small**. Docker и Airflow для запуска не нужны.

## Как работает

```mermaid
flowchart LR
    Q[Вопрос] --> S[Поиск в справке]
    S --> G[Подготовка ответа]
    G --> C[Проверка фактов и полноты]
    C --> A[Ответ с цитатами или отказ]
    A --> T[Передача оператору по кнопке]
```

Сначала статьи разбиваются на небольшие фрагменты и сохраняются в индексе FAISS. Когда приходит вопрос, поиск выбирает пять близких по смыслу фрагментов. К ним добавляются условия из начала соответствующих разделов — они могут быть важны для ответа.

Затем модель готовит ответ и указывает, на какие места в документах она опирается. Цитаты и ссылки подставляет код. Проверка идёт в два этапа: сначала проверяются факты по цитатам, затем — отвечает ли получившийся текст на вопрос.

Если при пересказе потерялось исключение, программа может заменить этот пункт точной цитатой. Если проверку пройти не удалось, ответ не показывается. Распознанные вопросы о личных данных магазина, например о причине скрытия конкретного товара, отклоняются до генерации.

Проверки уменьшают риск выдуманных ответов, но не исключают его полностью. Число сходства в поиске тоже не означает, что ответ правильный.

## Запуск

Нужны Python, [Ollama](https://ollama.com/download/windows) и интернет для первой загрузки библиотек, статей и моделей. Готовые скрипты запуска написаны для Windows и PowerShell. Проект проверен на Python 3.14.

### Первый запуск

Установите и запустите Ollama. Откройте PowerShell в папке проекта, рядом с `app.py`, и выполните:

```powershell
# Создать окружение и установить библиотеки
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# Скачать статьи и подготовить поиск
.\.venv\Scripts\python.exe scripts/collect_docs.py
.\.venv\Scripts\python.exe scripts/search_docs.py build

# Скачать модель, если её ещё нет, и запустить приложение
.\scripts\start_app.ps1
```

После запуска откройте [http://127.0.0.1:8501](http://127.0.0.1:8501).

Скрипт сам подготовит модель `rag-support-qwen3` и создаст `.env` из примера. Первый запуск будет дольше из-за загрузки файлов. Для остановки приложения нажмите `Ctrl+C` в терминале.

### Следующие запуски

```powershell
.\scripts\start_app.ps1
```

Скрипт ищет окружение `.venv` в папке проекта или на уровень выше. Если ваше окружение находится выше, в ручных Python-командах замените `.\.venv` на `..\.venv`.

### Если PowerShell не запускает скрипты

После установки библиотек и подготовки поиска выполните команды вручную. Ollama должна быть запущена; при необходимости выполните `ollama serve` в другом терминале.

```powershell
ollama pull qwen3:4b-instruct
ollama create rag-support-qwen3 -f Modelfile
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
$env:HF_HUB_OFFLINE = '1'
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501 --server.fileWatcherType none --browser.gatherUsageStats false
```

### Настройки

Настройки подключения лежат в `.env`. Для локального запуска менять их не нужно:

```dotenv
LLM_BASE_URL=http://127.0.0.1:11434/v1
LLM_API_KEY=
LLM_MODEL=rag-support-qwen3
LLM_TIMEOUT_SECONDS=180
RAG_MIN_SCORE=
```

Ollama не требует API-ключа. `RAG_MIN_SCORE` оставлен пустым: порог сходства пока не подбирался. Приложение доступно только на локальном адресе компьютера.

### Обновление справки

```powershell
.\.venv\Scripts\python.exe scripts/collect_docs.py --refresh
.\.venv\Scripts\python.exe scripts/search_docs.py build
```

Первая команда заново скачивает статьи, вторая обновляет индекс. Без `--refresh` используются уже скачанные страницы. Если справка изменится, результаты ответов тоже могут измениться.

## Проверки

```powershell
# Проверить зависимости и запустить тесты без LLM
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

# Использовать уже скачанную модель поиска без обращения к Hugging Face
$env:HF_HUB_OFFLINE = '1'

# Проверить поиск
.\.venv\Scripts\python.exe scripts/search_docs.py evaluate

# Проверить ответы: Ollama должна быть запущена
.\.venv\Scripts\python.exe scripts/evaluate_answers.py
.\.venv\Scripts\python.exe scripts/evaluate_answers.py --cases data/validation_cases.json
```

Отчёты сохраняются в `data/evaluations/`. Для быстрой проверки первых двух вопросов добавьте к команде оценки `--limit 2`.

## С какими проблемами столкнулся проект

| Проблема | Как решалась |
|---|---|
| Бот выдавал общую причину из справки за причину скрытия конкретного товара | Добавлены правила, которые останавливают распознанные запросы к данным магазина до генерации |
| Поиск находил инструкцию, но пропускал условия перед ней | К найденным фрагментам добавляются условия из начала раздела |
| При пересказе терялось исключение, например разрешение логотипа бренда | Пункты списка разделены; при потере оговорки используется точная цитата |
| Проверяющий путал текст ответа с предположением в вопросе | Проверка фактов отделена от проверки того, отвечает ли текст на вопрос |
| Наличие ссылки создавало впечатление, что ответ верный | В проверочные вопросы добавлены критерии, а ответы разбираются по содержанию |
| Для пет-проекта хотелось обойтись без платного API | Модель запускается локально через Ollama |
